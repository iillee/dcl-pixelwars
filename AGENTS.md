No-base bridges live in `src/maze/level.ts`:

- A bridge is placed only when a lower straight occupies the same `(x, z)` cell, one `STEP` below, running along the perpendicular axis with both ends connected (a true crossover). The upper is a straight or ramp whose own ends already connect on its level. Being beside a lower tile or an open drop is not enough. A ramp cannot sit underneath: its high deck would rise into the slab.
- `BRIDGE_CHANCE` (0.75) and `BRIDGE_MAX` (3): how often a qualified underpass slot is realised. High enough that a map with several slots usually gets more than one. Picks are seeded, so every client and the server agree. If the roll gives none, one true crossover is still placed when a valid slot exists, and a second is placed whenever another slot still realises. One through-path crossing is enough (no lookout dead-end), so a level with only one legal slot still ships.
- The 2D net search prefers layouts that already have a perpendicular underpass slot. It does not grow 1–2 cell spurs or shrink a tile into an end. There are no dead-end or end tiles anywhere in the generated level (team bases are corner turns with two openings). Every generated level has no end tiles. True through-path crossovers are placed whenever a legal slot realises; the play grid stays 5×5 (a 7×7 trial made generation slower and did not raise the rate).
- `BRIDGE_Y_NUDGE` (0.046 m): lifts the slightly thinner bridge deck to the mass01 walking height.
- `BRIDGE_STYLE` is kept, but stacked underpasses always use the simple slab. The arched GLBs still have ~200 m legs that would cut through the lower corridor.
- Paint, mazeGraph and bots treat both floors as real tiles (`cellId` includes `ty`).
